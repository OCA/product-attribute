Merge attribute values that are the same one, such as "3-4kg" and
"3/4kg" created by different users, without touching the variants that
use them, and undo the merge if it was a mistake.

Since Odoo 18.0 nothing stops two values of an attribute from having the
same name, and deleting a value that archived variants use only archives
it, so duplicates appear easily. This module finds them and merges them:

- The product attribute values of the templates keep their id and only
  point to the kept value, so variants, their combinations and
  everything hanging from them (stock, sales, accounting) stay as they
  are.
- Every other stored reference to the merged values (for example a lot
  keeping the fishing area of its product) is moved to the kept value.
- The merged values are archived, not deleted, and every moved record is
  logged. Undoing the merge puts back the records that still hold the
  kept value; records created or changed after the merge keep their
  current value.
- The name of the kept value is chosen per language, filling the
  languages it lacks with the names of the merged values.

Usage
=====

Users in the *Product Manager* group can:

1. Open an attribute and press **Duplicates**. Values showing the same
   name in one of the languages of **Compare Names In** are grouped
   (case and spaces ignored). By default these are the languages of the
   internal users: translations nobody reviews can give two different
   values the same name. Tick **Ignore Accents and Punctuation** to also
   group names such as "2/3kg" and "2-3 kg", and **Search Again**.
2. Press **Merge** on a group, on the merge button of a value in the
   attribute form, or select values in a list of attribute values (core
   has no such list: a module such as ``product_attribute_value_menu``
   adds it) and use *Action > Merge*.
3. In the wizard, check the usage of each value, choose the **Value to
   Keep** and review its name in each language. Rows in orange are
   languages where the values show different names.
4. Press **Merge**. The merge record opens with the moved records; its
   **Undo** button reverts the merge.

When a product has the kept value and a merged one on the same attribute
line, the merged value is not merged on that product and stays active:
rename it so both can be told apart, or remove one of them from the
product. A merged value that the product only keeps on archived variants
is merged as usual.

Undo restores the merged values as they were: a value that was archived
before the merge stays archived.

The merges of an attribute are listed from the **Merges** button of its
form.

Known issues / Roadmap
======================

- Company dependent fields pointing to attribute values are not moved;
  the wizard warns how many records hold the merged values there.
- A record that gets a merged value in a transaction committed while the
  merge runs (after it started, before it locks the values) keeps the
  archived value.
- Values referenced by id in saved filters, default values or server
  actions keep pointing to the merged value.
- Generic references (``fields.Reference``, ``res_model``/``res_id``) to
  attribute values are not moved.
- A product having two of the values on the same attribute line is left
  as it is: merging those variants would mean merging products.
